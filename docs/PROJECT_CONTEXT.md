# 프로젝트 맥락 (작업 지시서 v1.0 요약, 2026-10-17)

## 목적
신호처리 및 인공지능 연구실 견학 고등학생(2026-10-21 수, 10-23 금)이 Joy-Con L/R로 3D 로봇 양손 집게를 조종한다. 학생 시범을 기록해 모방학습(Behavioral Cloning)을 하고, AI가 같은 과제를 스스로 시도하며, 교정(Takeover) 데이터로 점점 나아지는 과정을 **실제 학습·실제 평가 수치로** 보여준다.

## 학생에게 전할 메시지
1. AI는 사람의 행동을 보고 배울 수 있다. 2. 시범의 양과 질이 결과를 바꾼다. 3. 배우지 않은 상황에선 실수한다. 4. 실패 지점에서 교정하면 나아질 수 있다. 5. 연구는 수집→학습→평가→교정의 반복이다.

## 절대 규칙
- 성능 향상 연출, 사전 궤적 재생 금지. Replay는 학습 결과로 간주하지 않는다.
- 실제 실행 없이 성공 보고 금지. 검증 안 된 단계 위에 큰 코드 쌓지 않는다(Bottom-up).
- 규칙 기반 부분(파지 부착, 단계 전환)은 학습된 정책과 명확히 구분해 표시한다.
- 정식 DAgger 구현이라 주장하지 않는다("DAgger에서 영감을 받은 Interactive IL").
- 시스템 드라이버 설치·삭제, 보안 설정 변경은 사용자 승인 없이 하지 않는다. 기존 Python 환경 수정 금지.
- 엔진·하드웨어 연결 등 구조적 결정은 근거와 함께 사용자와 협의한다.

## 단계
Phase 0 환경 조사 → 1 Joy-Con L/R 연결 → 2 입력 추상화(InputProvider: JoyCon/Keyboard/Replay, Dead Zone·중립 보정·Debounce·타임스탬프·기록/재생) → 3 최소 3D 환경(테이블, 좌우 집게, 큐브, 목표 상자, 고정 카메라) → 4 양손 분류 게임(왼손 파랑→왼쪽 상자, 오른손 주황→오른쪽 상자, 사람이 15~30초에 성공 가능해야 함) → 5 시범 기록(고정 주기 (s,a), Episode ID, Seed, 실패 시범 별도 보존, JSONL/NPZ + 스키마 버전, Replay 검증) → 6 k-NN BC(특징 정규화, 연속/이진 행동 분리, 출력 제한·평활화, 데이터 밖 영역 처리, 모델 버전·저장) → 7 고정 평가 Seed 5~10개(미학습 배치 포함) 성공률·시간 → 8 Takeover 교정학습 → 9 통합 UI(화면 75% 3D, 25% 모드/시범 수/데이터 수/정책 버전/성공률). 두 번째 게임(양손 전달)은 첫 견학 필수 아님.

## 조작 (첫 버전)
왼쪽 스틱=왼손 X/Z 이동, 오른쪽 스틱=오른손 X/Z 이동, ZL/ZR=집게 닫기. 고정 높이, 집으면 자동 들어올림 허용. IMU 3D 위치 복원은 하지 않는다(절대 위치 센서 아님).

## 일정
10/17 환경·Joy-Con 연결·로깅 → 10/18 입력 표준화·3D·양손 조작 → 10/19 기록·첫 BC·AI 실행 → 10/20 평가·교정·UI·리허설 → 10/21 견학 → 10/22 안정화 → 10/23 견학.

## 장애 대비
Keyboard Provider, 검증된 시범 데이터, 이전 정책 체크포인트, 정상 시연 영상. 재생 시 실시간 학습과 명확히 구분.
