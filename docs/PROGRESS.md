- **IMU 서브샘플 순서**: 리포트 내 3개 샘플은 [0]이 최신, [2]가 가장 오래됨(Phase 1 로그로 확인: [2]→[0] 순서가 [0]→[2]보다 신호 거칠기 40배 작음). `JoyConInputProvider`가 `[-1]`(10ms 늦은 샘플)을 최신으로 쓰던 것을 `[0]`으로 수정.

## 알려진 문제
- **R→L IMU 축 매핑 미검증.** 두 조이콘을 손으로 붙여 기울이는 방식은 실측 데이터에서 실패(같이 회전한 구간이 짧고, R 가속도 크기가 정지 시 1.09G로 9% 큼). 세션 중 상관계수 방식이 낸 (1,−1,−1)은 근거 불충분으로 폐기. 현재 R의 accel/gyro는 센서 좌표계 그대로이며 프레임 `meta.imu_frame_verified=false`. IMU는 MVP 필수가 아니므로 보류. 필요해지면 "책상 위 정지 자세 3가지"로 측정 (`scripts/estimate_axis_map_from_recording.py` 활용 가능).
- **조이콘 절전·고착 (2026-10-20 원인 확인, `docs/JOYCON_LINK_MANAGER_PLAN.md` 9절)**: 조이콘은 마지막 버튼 입력 15분 뒤 스스로 잠든다(4회 모두 14:58~15:06. 움직임·진동·램프 출력으로는 연장되지 않고, 버튼만 타이머를 처음부터 다시 세게 함). 잠든 뒤 깨우면 Bluetooth 연결과 HID 목록 표시까지는 되지만 HID 입출력이 죽어 있는 "고착"이 자주 생기며, 재페어링으로만 풀린다. 대응: 연결 관리자 `scripts/joycon_manager.py`(고착 자동 감지 → SYNC 한 번으로 재페어링, 실기에서 버튼부터 준비됨까지 50~60초; 마지막 버튼 15분 카운트다운과 남은 3분 경고를 관리자 창과 ALOHA 앱 화면에 표시), 수동 `scripts/joycon_pair.py LR`(24~56초). 견학 리허설은 아직. 이전의 "재연결 46~54초" 관찰은 같은 현상의 일부로 본다.
- Intel 내장 Bluetooth Error 상태 (Realtek USB 사용 중)
- 프로젝트 경로 한글 포함 → Phase 3 엔진에서 확인
- joycon-python 라이선스 파일 확인 필요
