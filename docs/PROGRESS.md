### 사후 수정 (2026-10-17 밤)
- **IMU 서브샘플 순서**: 리포트 내 3개 샘플은 [0]이 최신, [2]가 가장 오래됨(Phase 1 로그로 확인: [2]→[0] 순서가 [0]→[2]보다 신호 거칠기 40배 작음). `JoyConInputProvider`가 `[-1]`(10ms 늦은 샘플)을 최신으로 쓰던 것을 `[0]`으로 수정.
- **IMU 켜짐 직후 과도 구간**: 6축 센서 활성화 후 약 1초간 가속도 z가 0.94G±0.22로 불안정. 정지 기준값을 잡을 때 첫 1초는 쓰지 말 것.
- **모션 조작 의미 재정의 요청**: 사용자는 "기울이기 = 로봇 팔 자세·높이, 손을 옮긴 방향 = 이동"을 원함(현재 구현은 기울기 = 이동 속도). 방식 결정 대기 — 분석은 `잡동사니/blog_materials/07_모션_조작_설계와_수정.md`.

### 이동 방식 실측: A안(IMU 스트로크 + ZUPT) (2026-10-18)
- 녹화 `tests/manual/record_motion_strokes.py`, 분석 `scripts/analyze_strokes.py` (leave-one-out).
- 데이터: 공중 세션 2회 × 16회 = 32회 (`strokes_desk_R_20261018_010220.jsonl`은 파일명과 달리 **공중**에서 수행 — 사용자 확인).
- 결과(최선 방법 zupt2 = 전후 중력 보간 + ZUPT): 방향 30/32, 오차 5cm 이내 7/32, 오차 중앙값 7.7cm, 거리 배율 세션별 0.84/0.46, 10cm·20cm 구분 69%.
- 판정: **A 단독으로는 "손을 옮긴 만큼 이동" 불가** (방향만 신뢰). 다음: A′(방향만 + 고정 칸) / B(웹캠 손 위치 + 조이콘 자세) / C(B+IMU 융합) 중 결정 대기. 웹캠 ABKO APC925 QHD 연결 확인.

### Phase 3 알려진 문제
- 화면이 기본 도형이라 투박함 → 에셋 교체 예정(후보 조사 완료, 스타일 결정 대기). 렌더링 분리로 게임·학습 코드 영향 없음.
- 가리키기 모드는 짧게만 사용(504프레임) → 손맛 피드백 필요. 보정의 pitch 축이 yaw와 완전 직교하지 않음(내적 −0.33/−0.14, 기울일 때 비틀림 포함).
- 목표 시간(시범 15~30초) 미측정: 이번 확인은 모드 체험이 섞여 집기→놓기 간격만 2~4초. Phase 4에서 측정·조정.

## 알려진 문제
- **R→L IMU 축 매핑 미검증.** 두 조이콘을 손으로 붙여 기울이는 방식은 실측 데이터에서 실패(같이 회전한 구간이 짧고, R 가속도 크기가 정지 시 1.09G로 9% 큼). 세션 중 상관계수 방식이 낸 (1,−1,−1)은 근거 불충분으로 폐기. 현재 R의 accel/gyro는 센서 좌표계 그대로이며 프레임 `meta.imu_frame_verified=false`. IMU는 MVP 필수가 아니므로 보류. 필요해지면 "책상 위 정지 자세 3가지"로 측정 (`scripts/estimate_axis_map_from_recording.py` 활용 가능).
- **재연결이 느림**: 해제 후 재연결까지 약 46~54초(3회 관찰). 장치가 Windows HID 목록에 다시 나타나기 전 시간이 대부분이며, 사용자가 버튼을 언제 눌렀는지는 기록되지 않아 원인(조이콘/Windows/코드) 미확정. 시연 중 연결이 끊기면 키보드 대체 입력으로 진행하는 운영 대책 필요.
- Intel 내장 Bluetooth Error 상태 (Realtek USB 사용 중)
- 프로젝트 경로 한글 포함 → Phase 3 엔진에서 확인
- joycon-python 라이선스 파일 확인 필요
